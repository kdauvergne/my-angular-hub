🗺️ 1. Déclarer les Routes & Activer le Router

Table de routage (app.routes.ts)

Chaque objet Route associe un chemin (path sans slash initial) à un composant.

  • Redirection initiale : { path: '', redirectTo: 'home', pathMatch: 'full' } redirige la racine / vers /home.
  • Lazy Loading (loadComponent) : Télécharge le code JavaScript d'une page uniquement lorsque l'utilisateur la visite, accélérant le démarrage de l'application.
  • Route Wildcard (**) : Intercepte toutes les URL inexistantes (page 404). Elle doit impérativement être placée en dernière position.

🔗 2. Naviguer : Template vs TypeScript

Dans le Template HTML

routerLink

Remplacez toujours href par routerLink (importé depuis @angular/router) pour éviter le rechargement complet de la page. Ajoutez routerLinkActive pour styliser le lien actif.

Depuis le TypeScript

inject(Router)

Pour rediriger l'utilisateur après une action (soumission d'un formulaire, connexion réussie), injectez le service Router et appelez .navigate([...]).

Standard Moderne

🛡️ 4. Protéger les Routes avec un Guard Fonctionnel

Le type CanActivateFn

Un Route Guard est une fonction exécutée par Angular avant d'activer une route. Elle permet de vérifier si l'utilisateur est authentifié ou possède le bon rôle.

  • Retourner true : autorise l'accès à la page.
  • Retourner false : bloque la navigation.
  • Retourner un UrlTree (router.createUrlTree(['/login'])) : annule la navigation et redirige vers la page de connexion.

🎯 Bonnes pratiques à retenir

1. Ordre des routes crucial Angular évalue le tableau routes du haut vers le bas et s'arrête à la première correspondance. Placez toujours les routes spécifiques avant les routes dynamiques, et ** tout à la fin.
2. Lazy Loading systématique Privilégiez loadComponent: () => import(...) pour vos pages secondaires afin de réduire le temps de chargement initial de votre application.
3. Sécurité côté Backend Un CanActivateFn améliore l'expérience utilisateur en masquant les pages privées, mais ne remplace jamais la vérification du token JWT côté serveur (API).
