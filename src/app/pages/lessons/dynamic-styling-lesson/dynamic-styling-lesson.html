🏷️ 1. Classes Dynamiques : [ngClass] vs [class]

Directive [ngClass]

Historique

Nécessite d'importer NgClass depuis @angular/common. Permet de passer un objet dont les clés sont des classes CSS et les valeurs des conditions booléennes.

Liaison Native [class.*]

Standard Moderne

Intégrée directement au moteur d'Angular (zéro import, plus performante). Utilisez [class.ma-classe]="condition" ou [class]="expression".

🖌️ 2. Styles Inline : [ngStyle] vs [style.*]

Directive [ngStyle]

Historique

Nécessite d'importer NgStyle depuis @angular/common. Utile uniquement si vous recevez un objet de styles complet pré-construit côté TypeScript.

Liaison Native [style.*]

Standard Moderne

Permet de lier directement n'importe quelle propriété CSS avec son unité ([style.width.%], [style.font-size.px]) ou une variable CSS ([style.--var]).

🎯 Bonnes pratiques avec Tailwind CSS & Angular 22

1. Privilégier la syntaxe native L'équipe Angular recommande d'utiliser [class.*] et [style.*] par défaut : plus rapides à l'exécution et sans aucun import supplémentaire.
2. Règle d'or Tailwind CSS Écrivez toujours les noms de classes en entier (ex. 'bg-success'). Ne construisez jamais une classe par concaténation ('bg-' + status), sinon Tailwind la supprimera lors du build !
3. Variables CSS dynamiques Pour des valeurs calculées à la volée (barres de progression, coordonnées), injectez une variable CSS avec [style.--progress]="val() + '%'".
