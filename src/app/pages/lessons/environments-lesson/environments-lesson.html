📁 1. Le dossier src/environments/

Génération & Rôle des fichiers

Par défaut, un nouveau projet Angular ne crée pas le dossier environments/ pour alléger l'arborescence. Une seule commande CLI suffit à le générer et à configurer angular.json.

  • environment.ts : Contient la configuration de référence (celle de production). C'est ce fichier que TypeScript vérifie pour le typage.
  • environment.development.ts : Contient les valeurs de votre machine locale (ex: API sur localhost:3000, logs activés).

La règle d'or des imports

📄 3. Pourquoi n'y a-t-il pas de fichier .env natif ?

Critère Approche Angular (environments/*.ts) Fichier .env (Node.js / Vite / CI-CD)
Typage & Autocomplétion ✅ Natif en TypeScript (objets, tableaux, booléens). ⚠️ Tout est lu sous forme de string.
Support natif par Angular CLI ✅ Intégré de base via fileReplacements. ❌ Ignoré par le navigateur (nécessite @ngx-env/builder ou SSR).
Usage en entreprise Configuration structurelle par environnement (dev, staging, prod). Injection dynamique de variables lors d'un déploiement Docker / GitHub Actions.

Comment utiliser un .env si nécessaire ?

Un navigateur web ne peut pas lire un fichier .env sur le disque. Les variables sont toujours injectées au moment du build :

  • En mode SSR (Server-Side Rendering) : le serveur Node.js d'Angular (server.ts) accède directement à process.env pour les vrais secrets.
  • Côté Navigateur : le paquet communautaire officiel @ngx-env/builder permet d'exposer dans import.meta.env uniquement les variables préfixées par NG_APP_.

🛡️ Sécurité & Bonnes pratiques indispensables

1. Zéro secret dans le Front-End ! Tout ce qui se trouve dans environment.ts ou dans une variable NG_APP_ est compilé dans le JavaScript téléchargé par le navigateur. N'y mettez jamais de mot de passe BDD, clé privée Stripe ou secret JWT : gardez-les sur votre API backend.
2. Structure d'objet identique Conservez exactement les mêmes clés dans environment.ts et environment.development.ts afin d'éviter toute erreur de compilation TypeScript lors du ng build final.
3. Fichiers locaux & .gitignore Si vous utilisez un fichier .env local ou un environment.local.ts contenant vos paramètres personnels, ajoutez-le systématiquement au fichier .gitignore et fournissez un modèle .env.example à l'équipe.
