🔥 Firebase & @angular/fire (BaaS)

Déployez une application full-stack temps réel sans gérer de serveur grâce au modèle Backend-as-a-Service (BaaS) de Google et son intégration officielle Angular.

☁️ 1. Le modèle BaaS & le Wrapper @angular/fire

🚀 Qu'est-ce qu'un BaaS ?

Un Backend-as-a-Service fournit une infrastructure serveur prête à l'emploi (authentification, bases de données, stockage de fichiers, hébergement) consommable directement depuis le front-end via un SDK sécurisé.

🅰️ Pourquoi @angular/fire ?

C'est la bibliothèque officielle qui enveloppe le SDK JavaScript de Firebase pour l'adapter à l'écosystème Angular : Injection de dépendances (inject()), flux RxJS compatibles toSignal(), et support du SSR.

⚡ Synchronisation Temps Réel

Contrairement à une API REST classique (requête/réponse ponctuelle), Firebase maintient un canal ouvert (WebSockets) : toute modification en base met instantanément à jour l'interface de tous les utilisateurs connectés.

⚙️ 2. Installation & Configuration (app.config.ts)

Architecture Modulaire (Tree-Shakeable)

La commande ng add @angular/fire installe le paquet et configure automatiquement votre projet. Vous n'importez que les providers dont vous avez réellement besoin afin de garder un bundle léger.

🔐 3. Authentification (@angular/fire/auth)

Gestion complète des sessions utilisateurs

Firebase Auth gère l'inscription, la connexion (Email/Mot de passe, Google, GitHub, Apple...), la réinitialisation de mot de passe et le rafraîchissement automatique des jetons JWT.

Synergie avec Angular Signals :

La fonction user(this.auth) retourne un Observable<User | null> qui émet à chaque connexion ou déconnexion. En l'enveloppant dans toSignal(), toute votre application (Navbar, Guards, Profil) réagit instantanément.

🗄️ 4. Les Deux Bases de Données : Firestore vs Realtime Database

Critère Cloud Firestore (Recommandé par défaut) Realtime Database (Historique / Ultra-rapide)
Modèle de données Collections contenant des Documents (typés, indexés, sous-collections). Un seul grand arbre JSON imbriqué.
Requêtes & Filtrage Requêtes complexes combinées (where(), orderBy(), limit()). Tri ou filtrage limité à une seule propriété à la fois.
Cas d'usage idéal Applications métier, catalogues produits, profils utilisateurs, réseaux sociaux. Présence en ligne (en ligne/hors ligne), curseurs collaboratifs, télémétrie IoT.

Cloud Firestore

@angular/fire/firestore

Utilisez collectionData(ref, { idField: 'id' }) pour recevoir un tableau d'objets fortement typés incluant automatiquement l'identifiant unique de chaque document.

Realtime Database

@angular/fire/database

Pointez vers un chemin de l'arbre JSON avec ref(db, 'chemin'), ajoutez des entrées via push() et écoutez la liste en direct avec listVal().

📦 5. Stockage de Fichiers (@angular/fire/storage)

Héberger images, vidéos et documents

Les bases NoSQL (Firestore / RTDB) ne sont pas conçues pour stocker des fichiers lourds. On envoie le fichier dans un Bucket Cloud Storage, puis on enregistre uniquement son URL de téléchargement (getDownloadURL()) dans Firestore.

  • ref(storage, 'chemin/fichier') : cible l'emplacement dans le bucket.
  • uploadBytesResumable() : gère les coupures réseau et permet le suivi en temps réel.
  • percentage(task) : Observable fourni par @angular/fire pour alimenter une barre de progression.

🎯 Règles d'or Firebase en Production

1. Firebase Security Rules Ne laissez jamais vos règles en mode test (allow read, write: if true;) en production ! Protégez vos collections et buckets directement depuis la console Firebase en vérifiant request.auth != null.
2. Clé API publique mais encadrée La firebaseConfig présente dans le front-end identifie votre projet mais ne donne aucun droit administrateur. Restreignez toutefois les domaines autorisés (HTTP Referrers) dans Google Cloud Console.
3. Éviter les lectures inutiles Chaque lecture de document Firestore est comptabilisée dans les quotas. Utilisez limit() sur les listes longues et préférez getDocs() à collectionData() si la donnée n'a pas besoin d'être temps réel.
